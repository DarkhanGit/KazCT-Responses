# Текст обновления регистрации №3 (OSF «Update registration», osf.io/sdgye) — процедура обучения энкодеров

Готово к вставке (04.11.2026). Файл для загрузки в nx6hj: results/diag_xlmr_summary.csv (только метрики), analysis/diag_encoder.py.

**Reason for update:**
Registration update 3 (4 November 2026) — change of the encoder training schedule. The registration fixed: learning rate 2e-5, batch size 16, up to 10 epochs with early stopping on the validation split. In the first full run of XLM-RoBERTa base under this procedure (constant learning rate, early stopping on validation QWK with patience 2), the models degenerated: from the second epoch on they predicted a single score class (validation QWK = 0), so early stopping ended training after three or four epochs with an essentially untrained model. On the test folds already scored in that run (zero-shot and few-shot, Kazakh target), XLM-RoBERTa reached QWK of about 0.20, below the length-only baseline (0.64); we report this openly. To choose a replacement without using test data, a diagnostic was run on the validation parts of the training folds only (mono-KZ, five prompts × five folds, seed 11; no test fold was predicted): registered procedure, validation QWK 0.088 (78% of predictions in one class); 10% warm-up with linear decay and patience 2, 0.102; warm-up and linear decay over 10 epochs with the best validation epoch retained, 0.237; the same over 20 epochs, 0.669 (median best epoch 13). The last schedule is adopted for stage-one training of all encoders (XLM-RoBERTa base, mBERT, Kaz-RoBERTa) in all conditions: learning rate 2e-5 with 10% linear warm-up and linear decay, batch size 16, 20 epochs, the epoch with the highest validation QWK retained; validation split, maximum length, seeds and all other settings are unchanged. The few-shot second stage (three epochs on the k target examples, constant learning rate, no validation) is unchanged. All encoder runs are repeated with this schedule; the predictions of the first run are kept and reported in an appendix. Feature-based baselines are unaffected. Diagnostic summary and code: diag_xlmr_summary.csv, diag_encoder.py in the project files. The only text change in this update is the corresponding sentence in Analysis Plan → Statistical models.
